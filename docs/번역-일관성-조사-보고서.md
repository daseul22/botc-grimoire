# 한국어 번역 일관성 전수 조사 보고서

> 작성일 2026-06-15 · 대상 `data/characters.json` (직업 183종)

## 0. 처리 결과 (2026-06-15 적용 완료)

조사 후 아래 11개 용어를 **UI 정규어 기준으로 통일 적용**했습니다. 모든 치환은 조사(particle) 일치를 보정했고, 병렬 검증 에이전트가 잡은 비문 5건(`*외지인*과`, `리마인더)로`, 이중조사 등)까지 교정 후 **변이 0건·비문 0건**으로 검증했습니다.

| 영문 | → 정규어 | 영문 | → 정규어 |
|---|---|---|---|
| Townsfolk | 마을주민 | dusk | 황혼 |
| Outsider | 외지인 | Hermit | 둔세자 |
| reminder token | 리마인더 | Poisoner | 독살범 |
| nominate | 지목 | Fortune Teller | 점쟁이 |
| good/evil team | 선한 팀 / 악한 팀 | register as | ~로 인식되다 |
| in play | 게임에 있는/있다 (부정: 게임에 없는/없다) | | |

**수정 불필요로 확정된 항목:**
- **execute** → `처형`(301)으로 완전 일관. (※초안의 "처단(2)"은 **오탐** — `처단자`는 Slayer 직업명, 무관)
- **register 탐지측** → `감지`는 영문 detect에 대응하는 별개 개념이라 유지.
- 고정 토큰명 `*이 캐릭터는 참여하지 않습니다*`(NOT IN PLAY 토큰), "투표에 참여", fabled의 사교적 "참여"는 의미가 달라 유지.

## 1. 조사 개요

- **대상 필드**: 각 직업의 `name` / `ability` / `detail` / `howTo[]` / `flavor` / `jinxes[]` / `setupNote` / `firstNight.reminder` / `otherNight.reminder`
- **방법**: 영문 원문(en)이 일관된 용어를 쓰는 지점에서, 대응하는 한국어(ko)가 어떤 표현을 쓰는지 **동시출현(co-occurrence)** 으로 집계. 추가로 UI 정규 용어(`lib/constants.ts`·`lib/markers.ts`·`components/*`)와 대조해 "데이터 ↔ UI" 충돌도 확인.
- **핵심 결론**: 영문은 일관적이나 한국어는 핵심 게임 용어 다수가 **2~4가지로 혼용**된다. 특히 **팀명 · 리마인더 토큰 · register · in play · nominate · dusk** 가 심각하다. 반면 Minion·Demon·성향·dawn 등은 완전히 일관적이다.

## 2. 심각도별 결과

### 🔴 A등급 — 체계적·대량 불일치 (최우선 수정)

#### A-1. Townsfolk → `마을주민`이 데이터에 **0회**, 대신 `주민`/`마을사람` 혼용
- 영문 `Townsfolk`가 등장하는 **92개 필드 중 UI 정규어 `마을주민`은 단 한 번도 안 쓰임**.
- 대신 두 가지로 갈림 — **간결 필드(`ability`/`firstNight`/`setupNote`)는 `주민`**, **서술 필드(`detail`/`howTo`)는 `마을사람`**.
- **같은 직업 안에서도 혼용**: virgin·washerwoman·drunk·professor·apprentice·nodashii·vigormortis·pixie·bountyhunter·huntsman·xaan 등은 `ability`엔 "주민", `detail`엔 "마을사람".
  - 예) virgin `ability`: "…지목한 플레이어가 **주민**이라면" / `detail`: "…지명자가 **마을사람**이면".
- UI(`constants.ts` TEAMS)와 SeatView 등은 `마을주민` 사용(11회). → **데이터만 동떨어져 있음.**

#### A-2. Outsider → `외지인`(정규)과 `아웃사이더`(음역) 혼용
- 영문 `Outsider` 86필드 중 `외지인` 26 / `아웃사이더` ~60. 음역이 더 많음.
- **간결 필드는 `외지인`, 서술 필드는 `아웃사이더`** — Townsfolk와 동일한 패턴.
  - 예) spy `ability`: "주민 또는 **외지인**으로 위장" / `detail`: "마을사람이나 **아웃사이더**로 등록".
- UI는 `외지인`(8회), `아웃사이더`는 0회.

#### A-3. reminder token → `리마인더`(97) vs `알림`(82) — 거의 반반
- 영문 `reminder` 184필드에서 `리마인더 토큰` 97, `알림(토큰)` 82.
- 흥미롭게도 **한 직업 안에서 둘 다 쓰는 경우는 0** → 직업마다 통째로 한쪽을 쓰지만, **직업 간에는 절반씩 갈림**(번역 출처가 둘인 정황). 표현 통일 필요.

#### A-4. "in play / in the game" → 4가지 표현
- `게임에 있는`(51) / `게임에 참여하는`(19) / `인플레이`(16, UI 정규) / `게임 속`(1).
- **12개 직업이 한 직업 안에서 혼용**: librarian·baron·godfather·philosopher·pithag·stormcatcher·engineer·damsel·widow·leviathan·ojo·sentinel.
- UI는 `인플레이`(16회) 사용. 데이터는 `게임에 있는`이 다수 → 충돌.

#### A-5. nominate → `지명`(61) vs `지목`(17) + **데이터 ↔ UI 정반대**
- **같은 직업 내 혼용 16종**: virgin·bishop·judge·towncrier·witch·butcher·ventriloquist·princess·banshee·golem·zealot·goblin·fearmonger·psychopath·riot·gnome.
- ⚠ **UI는 `지목`(41회), `지명`은 0회** — 데이터는 `지명` 다수. 프로젝트 전체 단일화 결정 필요(아래 §4).

### 🟠 B등급 — 핵심 메커니즘 용어, 혼용 다수

#### B-1. "register (as)" → `등록`(11) / `인지·인식`(6) / `감지`(5) / `오인` / `~로 보이다`
- 핵심 메커니즘인데 4가지 이상으로 번역. **fortuneteller·recluse·spy·mathematician 내부 혼용**.
- "등록"은 *register*의 직역이지만 한국어로 어색함. 예) spy `detail` "…악으로 **등록**될 수 있습니다" vs recluse jinx "악으로 **오인**" vs soldier jinx "악팀으로 **오인**".

#### B-2. dusk → `황혼`(10, UI 정규) vs `해질녘`(19)
- **8개 직업이 내부 혼용**: sailor·innkeeper·minstrel·goon·barista·bonecollector·organgrinder·xaan.
  - 예) xaan `ability`: "**황혼**까지 중독" / `detail`: "**해질녘**까지 중독".
- `markers.ts`는 `황혼까지`(duration `dusk`) 사용 → **황혼**으로 통일 권장.

## 6. 권고 작업 순서

1. **§4 충돌 항목 표준 확정** (특히 nominate=지목/지명, in play=인플레이/게임에 있는) — 결정 없이는 데이터 수정 방향이 안 정해짐.
2. **A등급 일괄 치환** (Townsfolk·Outsider·reminder·in play·nominate) — 영향 직업이 많아 스크립트 기반 치환 + 수동 검수 권장.
3. **B등급(register·dusk)**, **C등급(직업명 오기·stray)** 순으로 정리.
4. 치환 후 `npm run db:seed`로 DB 재생성(데이터 진실은 `data/*.json`).
