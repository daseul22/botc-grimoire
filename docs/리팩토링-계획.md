## 전제: 이 코드베이스는 이미 건강하다

분석 결과 아키텍처는 견고하다 — 정체성↔페이즈 스냅샷 분리, 순수/서버 경계, "액션이 Game
반환→setGame" 단일 사용자 모델, ResultKind 6종+자유텍스트로 183직업 커버. **전면 재작성이
아니라, 이미 좋은 뼈대 위에서 "중복으로 인한 드리프트(drift) 버그"와 "비대한 파일"을 정리하는
점진적·동작 보존 리팩토링**이다.

## 설계 원칙 (과설계 방지)

1. **동작 보존(behavior-preserving)이 기본.** 의도적 behavior 변경은 Stage 7에서만, 사용자 결정과 함께.
2. **추상화는 실제 중복/통증이 있을 때만.** 상태관리 라이브러리·이벤트버스·DI 도입 금지. 단일 사용자 로컬 앱.
3. **확정 설계결정을 거스르지 않는다** (정체성↔스냅샷 분리, 서버 권위 setGame, 시트 전체 전달, 순수/서버 경계, JSON+SQLite).
4. **각 단계는 독립적으로 머지 가능**하고, 끝나면 빌드+스모크 통과를 확인한다.
5. **낮은 위험·높은 가치부터.** 죽은 코드→공유 상수→순수 헬퍼(드리프트 버그 제거)→엔진 정리→컴포넌트 분해 순.
6. **테스트 인프라는 최소.** 테스트 프레임워크가 없으므로, 추출한 *순수 함수 중 정확성이 가장 민감한 소수*에만
   선택적으로 가벼운 단위 테스트를 붙인다(의무 아님). 그 외엔 빌드 + 수동 스모크 체크리스트로 검증.

## 검증 방법 (모든 단계 공통)

- `npm run build`(또는 `npx tsc --noEmit` + `npm run lint`) 통과 — 타입/빌드 가드.
- 수동 스모크: 게임 생성 → 1일차 밤 셋업(블러핑/위장) → 행동 기록 → 페이즈 진행 → 낮 투표/처형 →
  과거 페이즈 열람 → 마커 토글 → 전체화면 첩자 시점 → PNG 내보내기 → 종료/복기. (해당 단계가 건드린 흐름만.)
- 코드 작성 전 `node_modules/next/dist/docs/` 관련 가이드 확인(AGENTS.md 규칙) — 특히 서버 액션을 손대는 Stage 4.
